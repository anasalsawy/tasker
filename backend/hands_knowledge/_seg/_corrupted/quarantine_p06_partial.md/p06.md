## 6. Jump Lists: the recent-items API you can read

Right-clicking a taskbar icon shows the **Jump List** — pinned tasks, recent documents, frequent items. This is a real, on-disk data source:

```
%APPDATA%\Microsoft\Windows\Recent\AutomaticDestinations\   # per-AUMID automatic lists
%APPDATA%\Microsoft\Windows\Recent\CustomDestinations\      # app-supplied custom entries
```

The folder name is a stable hash of the app's AppUserModelID. To answer "what has this app been opening?", resolve the AUMID (from `.lnk` extra data or `Get-StartApps`) and enumerate the matching folder. Files inside (`<hash>.automaticDestinations-ms`) are OLE structured-storage blobs whose streams hold PIDLs, display names, and run counts; the display name stream is the cheap read, full path reconstruction (IDList → parse name via `SHGetRealIDL`/`SHParseDisplayName`) is what Explorer does when clicking an entry. Raw names render without digging when hand-editing an audit — but do NOT hand-edit delete the whole file = wipe that app's Recent items.

The whole-tree alternative: `%APPDATA%\Microsoft\Windows\Recent\*.lnk` is the plain **Recent** folder (one `.lnk` per file, all apps mixed, Explorer shell "Recent locations" and Office Pinned/read routes into it, keyed only by opening presence-level or new Sort "Options-Memory page" "Run"黔      …).
